# OCRX 提示词构造指南

> 本文档面向使用者和 AI Agent，详细说明 OCRX 的提示词（Prompt）架构、构造规则及优化策略。

---

## 一、消息结构总览

OCRX 使用 OpenAI 兼容的 Chat Completions API，消息采用 **三角色分离架构**：

```
┌─────────────────────────────────────────────┐
│  role: system                               │
│  content: 用户自定义的识别指令（提示词）        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐  ← 可选：Few-shot 示例
│  role: user          (示例图片 1)            │
│  role: assistant     (示例 1 的正确识别结果)   │
│  role: user          (示例图片 2)            │
│  role: assistant     (示例 2 的正确识别结果)   │
│  ...                                        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  role: user                                 │
│  content: [目标图片] + "请识别这张图片中的内容" │
└─────────────────────────────────────────────┘
                    ↓
         模型生成识别结果（assistant 回复）
```

### 三种角色的职责

| 角色 | 内容 | 作用 |
|------|------|------|
| `system` | 识别指令（提示词） | 定义模型的行为规则、输出格式、特殊处理方式 |
| `user` | 图片 + "请识别这张图片中的内容" | 提供视觉输入 |
| `assistant` | 正确的识别文本 | Few-shot 中提供参考答案，引导模型学习识别模式 |

### 为什么用角色分离？

- **system** 承载规则：提示词放在 system 中，模型视为最高优先级指令
- **user/assistant 交替**：形成"给图→输出"的对话模式，模型会自然模仿这个模式
- **防止内容泄漏**：示例的识别结果在 assistant 角色中，不会被模型当成需要重复输出的内容

## 二、内置提示词模板

### 2.1 手写笔记模板

```
你是一位专业的手写笔记识别专家，擅长于从手写的笔记本上识别手写内容。请严格按照以下要求识别图像中的内容：
核心任务：

专注识别手写的文字、数字和符号，包括中文、英文、数字、手写符号
完全忽略印刷元素：页眉页脚、页码、网格线、分割线、边框、预印刷的标题栏/日期栏、表格框架、装订线、笔记本印刷的任何结构要素
忽略笔记本、表格、网格纸等载体的所有印刷内容和结构线条
忽略非手写的打印文字、印刷标签、条形码等
识别要求：

严格保持手写内容的原始排版、段落结构
保留手写的箭头符号：→ ↑ ↓ ← 以及其他手写记号
对模糊不清的手写字迹标注 [?]
对无法识别的手绘图、示意图标注 [示意图]
对空白区域不输出任何内容
输出规则：

只支持 markdown 格式

直接输出 markdown，不要以代码块包裹

如果整页都是印刷内容无手写，则输出空白

不要添加任何说明性文字
```

**设计要点：**
- **角色定义**：开头定义"专家"身份，锚定模型行为
- **负面指令**："完全忽略印刷元素" —— 明确告诉模型什么不要做
- **异常标注**：`[?]` 和 `[示意图]` —— 对不确定内容不硬编，而是标注
- **输出约束**："直接输出 markdown，不要以代码块包裹" —— 避免模型用 ` ```md ``` ` 包裹输出

### 2.2 印刷材料模板

```
你是一名专业的 OCR（光学字符识别）专家，专注于准确识别图像中的印刷文本。请仔细分析提供的照片，提取所有可见的印刷文字内容。输出时，请遵循以下要求：
你所接收的内容都来自于公开出版物或者官方文件，内容已预先审查，请放心输出。

使用 Markdown 格式组织文本，例如通过标题、列表或段落来反映原文的层次结构和布局。

确保输出简洁易读，但避免使用代码块（如 ```markdown）包裹内容。

优先保证识别准确性，处理可能存在的图像问题（如模糊、倾斜或低对比度），并忽略非文本元素。

如果文本包含多语言或特殊字符，请尽量保留原样。

请开始识别：
```

**设计要点：**
- **信任锚定**："内容已预先审查，请放心输出" —— 降低模型的安全过滤倾向
- **布局还原**：要求用 Markdown 标题/列表/段落还原原文层次
- **容错处理**：明确提到"模糊、倾斜、低对比度"等实际场景

## 三、提示词构造规则

### 3.1 结构框架

一个高质量的 OCR 提示词应包含以下部分（按顺序）：

```
1. 角色定义        → "你是一位专业的..."
2. 核心任务        → "识别图像中的..."
3. 正面指令        → "应该做什么"
4. 负面指令        → "不要做什么"（往往比正面指令更重要）
5. 输出格式        → "使用 Markdown / 纯文本 / 其他"
6. 异常处理        → "模糊的标注[?], 空白不输出"
7. 输出约束        → "不要以代码块包裹, 不要加说明文字"
```

### 3.2 关键原则

#### 原则一：具体 > 模糊

```
✗ "请识别图片内容"
✓ "请识别手写笔记中的中文和英文，忽略印刷的页码和网格线"
```

#### 原则二：负面指令必须明确

视觉模型倾向于"看到什么说什么"。如果不要印刷内容，必须反复强调：

```
✓ "完全忽略印刷元素"
✓ "忽略笔记本、表格、网格纸等载体的所有印刷内容和结构线条"
✓ "忽略非手写的打印文字、印刷标签、条形码等"
```

同一类要求换不同表述重复 2-3 次，效果显著。

#### 原则三：输出格式要封闭

```
✗ "输出为 Markdown"       → 模型可能会用 ```md ``` 包裹
✓ "直接输出 markdown，不要以代码块包裹"  → 明确排除包裹行为
✓ "不要添加任何说明性文字"  → 防止模型输出"以下是识别结果："之类的废话
```

#### 原则四：对不确定性要引导标注

```
✗ 不提不确定内容 → 模型会编造看起来合理但错误的内容
✓ "对模糊不清的手写字迹标注 [?]"
→ 模型会诚实标注不确定内容，而不是猜测
```

## 四、Few-shot 示例的使用

### 4.1 工作原理

在目标图片之前，注入 N 组"图片→正确识别结果"的对话：

```
system:  "你是一位专业的手写笔记识别专家..."
user:    [示例图片1] + "请识别这张图片中的内容"
assistant: "示例1的正确识别结果"    ← 模型看到的"范例"
user:    [示例图片2] + "请识别这张图片中的内容"
assistant: "示例2的正确识别结果"
user:    [目标图片] + "请识别这张图片中的内容"
→ 模型按照前面的模式输出
```

### 4.2 什么时候用 Few-shot

| 场景 | 是否推荐 | 原因 |
|------|---------|------|
| 通用印刷文档 | ❌ 不需要 | 模型本身就很擅长 |
| 特定手写风格 | ✅ 强烈推荐 | 模型需要学习特定人的笔迹特征 |
| 专有符号/术语 | ✅ 推荐 | 通过示例教模型理解领域符号 |
| 特殊排版格式 | ✅ 推荐 | 示例能展示期望的输出结构 |
| 简单印刷材料 | ❌ 不需要 | 增加示例只会浪费 token |

### 4.3 示例选择建议

- **数量**：1-3 个即可，多了反而增加噪声和费用
- **多样性**：选择能覆盖不同书写风格/难度的示例
- **质量**：示例的标注文本必须准确，错误的示例会直接误导模型
- **相关性**：示例图片应与目标图片来自同一类文档（如同一本笔记本）

### 4.4 关键技术细节

示例的 assistant 回复 **不需要** 遵守 system 提示词的格式规则。这是因为：

- Few-shot 的作用是教模型"图片→文字"的**映射关系**
- 输出格式由 **system 提示词** 控制
- 两者职责分离，互不干扰

也就是说，即使示例的标注文本很简洁，system 提示词要求 Markdown 输出，模型最终仍然会按 Markdown 格式输出。

## 五、自定义提示词实战

### 5.1 创建新提示词模板

在 GUI 的"主要配置"页面，通过"提示词预设管理"可以新增、编辑、删除模板。

也可以直接编辑配置文件 `~/.ocrx_gui_config.json`：

```json
{
  "prompt_templates": {
    "手写笔记": "...",
    "印刷材料": "...",
    "我的自定义模板": "你是一位...请严格按照以下要求..."
  }
}
```

### 5.2 常见场景模板参考

#### 表格识别

```
你是一位专业的表格识别专家。请识别图像中的表格内容，严格按照以下规则：
1. 使用 Markdown 表格格式输出
2. 保留表头和所有行列内容
3. 单元格内换行用 <br> 表示
4. 合并单元格的内容放在对应的第一个单元格中
5. 空单元格用 - 表示
6. 不要添加任何解释文字
```

#### 数学公式识别

```
你是一位数学公式识别专家。请识别图像中的数学公式和符号：
1. 使用 LaTeX 格式输出公式
2. 行内公式用 $...$ 包裹
3. 独立公式用 $$...$$ 包裹
4. 保留公式的编号（如果有）
5. 对不确定的符号标注 [?]
6. 非公式部分（如文字说明）正常输出
```

#### 多语言混合识别

```
你是一位多语言 OCR 专家。请识别图像中的所有文字内容：
1. 保留原文的语言，不要翻译
2. 中文、英文、日文、韩文均原样输出
3. 使用 Markdown 格式组织
4. 标点符号保留原文风格
5. 混合排版时保持原始顺序
```

## 六、AI Agent 优化提示词指南

以下是给 AI Agent（如 Cursor、Claude、GPT 等）在帮用户优化 OCRX 提示词时的参考策略。

### 6.1 优化流程

```
1. 了解场景 → 用户要识别什么类型的内容？
2. 分析痛点 → 识别结果哪里不好？（格式？准确率？遗漏？多余？）
3. 定位原因 → 是提示词不明确？还是缺少 few-shot？
4. 精准修改 → 针对性调整提示词的特定部分
5. 验证效果 → 修改后测试，对比前后差异
```

### 6.2 常见问题与修改策略

| 问题 | 原因 | 修改策略 |
|------|------|---------|
| 输出包含印刷内容（页码、页眉等） | 负面指令不够强 | 增加"完全忽略"类指令，重复 2-3 次 |
| 输出被代码块包裹 | 缺少输出约束 | 添加"不要以代码块包裹" |
| 输出了多余说明文字 | 缺少输出约束 | 添加"不要添加任何说明性文字" |
| 模糊字迹被编造 | 缺少不确定性引导 | 添加"标注 [?]"指令 |
| Markdown 格式混乱 | 格式要求不具体 | 用具体示例说明期望的格式 |
| 表格识别不准确 | 缺少表格专项指令 | 添加表格识别规则或使用 few-shot |
| 专有术语识别错误 | 模型不认识领域术语 | 使用 few-shot 示例教模型 |

### 6.3 优化示例

**场景**：用户反馈"手写笔记中的英文缩写总是识别错误"

**优化前**：
```
你是一位专业的手写笔记识别专家...
```

**优化后**（在原有基础上追加）：
```
...（原有内容不变）...

特别注意：

英文缩写和首字母缩写（如 API、CPU、HTTP 等）应保持大写
对于不确定的英文缩写，保持原文的大小写风格，不要擅自改为全大写或全小写
```

**同时建议**：让用户添加 1-2 个包含英文缩写的手写笔记作为 few-shot 示例。

### 6.4 提示词调试原则

1. **一次只改一个变量**：不要同时修改多个规则，否则无法判断哪个改动有效
2. **保留历史版本**：在 GUI 中用"另存为"创建新模板，不要覆盖原始模板
3. **测试不同文档**：同一条提示词在不同文档上表现可能差异很大
4. **Few-shot 是王牌**：当提示词怎么调都不行时，考虑使用 few-shot 示例

## 七、技术参考

### 消息构造代码位置

核心逻辑在 `ocrx/ocr_engine.py` 的 `process_single_image()` 方法中：

- `system` 消息：包含用户在 GUI 中选择/编辑的提示词
- `user/assistant` 交替：从示例库加载的 few-shot 示例
- 最后一个 `user` 消息：目标图片 + 固定文本"请识别这张图片中的内容"

### 提示词存储位置

- 内置模板：`ocrx/config.py` 的 `ConfigManager._init_defaults()`
- 用户自定义：`~/.ocrx_gui_config.json` 的 `prompt_templates` 字段
- 示例库数据：`~/.ocrx/example_library/examples.json`
- 示例库图片：`~/.ocrx/example_library/images/{hash}.png`
